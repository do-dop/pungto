# Pungto 실시간 일정 관리 기능 요구사항 명세서

## 1. 개요

### 1.1 목적

Pungto는 사용자가 협업방을 생성하고, 링크 또는 QR 코드를 통해 다른 사용자를 초대하여 함께 사용할 수 있는 실시간 협업 웹앱이다.

기존 Pungto에는 일정 화면이 존재하지만, 해당 기능은 실제 데이터 저장이나 실시간 공유가 적용된 완성 기능이 아니라 목업 또는 정적 화면에 가까운 상태이다. 본 개선의 목적은 이 일정 기능을 방 참여자들이 실제로 사용할 수 있는 실시간 일정 관리 기능으로 확장하는 것이다.

이번 개선을 통해 사용자는 방 안에서 일정을 생성, 조회, 수정, 삭제할 수 있으며, 같은 방에 접속한 다른 사용자도 변경된 일정을 실시간으로 확인할 수 있어야 한다.

### 1.2 범위

이번 요구사항 분석의 범위는 Pungto의 일정 관리 기능 개선에 한정한다.

포함 범위는 다음과 같다.

- 방별 일정 목록 조회
- 일정 생성
- 일정 수정
- 일정 삭제
- room ID 기반 일정 저장
- Supabase Realtime 기반 실시간 변경 반영
- 빈 제목 및 빈 날짜 입력 방지
- 일정 UI와 데이터 처리 로직의 분리
- 기존 채팅 및 칸반 기능에 대한 회귀 테스트

제외 범위는 다음과 같다.

- 반복 일정
- 알림 발송
- Google Calendar 등 외부 캘린더 연동
- 로그인 기반 권한 관리
- 자료, 알림, 개인 할 일 기능의 실제 구현

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| 방(Room) | 사용자가 생성하고 링크 또는 QR 코드로 공유하는 협업 공간 |
| 참여자(Member) | 닉네임과 브라우저 세션 ID를 기반으로 방에 입장한 사용자 |
| 일정(Schedule) | 특정 방에서 공유되는 제목, 날짜, 설명 기반의 협업 일정 |
| 실시간 반영 | 한 사용자의 데이터 변경이 새로고침 없이 다른 참여자 화면에 표시되는 것 |
| 목업 기능 | 화면은 존재하지만 실제 데이터 저장 또는 협업 동작이 구현되지 않은 기능 |

## 2. 이해당사자

| 이해당사자 | 관심사 |
|---|---|
| 방 생성자 | 팀 협업 공간을 만들고 일정을 공유하고 싶다. |
| 방 참여자 | 별도 가입 없이 방에 들어와 팀 일정을 확인하고 수정하고 싶다. |
| 개발자 | 기능 추가가 기존 코드 구조를 더 복잡하게 만들지 않기를 원한다. |
| 서비스 운영 관점 | 방별 데이터가 분리되고 실시간 기능이 안정적으로 동작해야 한다. |

| NFR-07 | 프로젝트는 lint와 build 검사를 통과해야 한다. | 테스트 가능성 | 정적 검사 및 빌드 확인 |

## 6. 외부 인터페이스 요구사항

### 6.1 사용자 인터페이스

- 사용자는 방 화면의 일정 메뉴에서 일정 목록을 확인할 수 있어야 한다.
- 사용자는 일정 추가 버튼을 통해 일정 입력 화면을 열 수 있어야 한다.
- 일정 입력 화면에는 제목, 날짜, 설명 입력 항목이 있어야 한다.
- 사용자는 기존 일정을 선택하여 수정할 수 있어야 한다.
- 사용자는 기존 일정을 삭제할 수 있어야 한다.
- 입력 오류가 발생하면 사용자가 원인을 이해할 수 있는 안내가 표시되어야 한다.
- 삭제 동작은 실수 방지를 위해 확인 후 수행되어야 한다.

### 6.2 소프트웨어 인터페이스

- 프론트엔드는 Next.js와 React 기반으로 구현한다.
- 일정 데이터는 Supabase에 저장한다.
- 실시간 변경 반영은 Supabase Realtime 이벤트를 이용한다.
- 일정 데이터는 현재 room ID를 기준으로 조회 및 저장한다.

## 7. 예외 조건 및 처리

| 예외 상황 | 처리 기준 |
|---|---|
| 제목 미입력 | 저장을 중단하고 제목 입력 안내를 표시한다. |
| 날짜 미입력 | 저장을 중단하고 날짜 입력 안내를 표시한다. |
| 저장 실패 | 오류 메시지를 표시하고 기존 화면 상태를 유지한다. |
| 수정 실패 | 오류 메시지를 표시하고 기존 일정 정보를 유지한다. |
| 삭제 실패 | 오류 메시지를 표시하고 일정 목록을 유지한다. |
| 다른 방 접속 | 현재 room ID에 해당하는 일정만 표시한다. |

## 8. 인수 조건

다음 조건을 모두 만족할 때 일정 관리 기능 개선을 완료한 것으로 판단한다.

- 일정 목록 조회가 가능하다.
- 일정 생성, 수정, 삭제가 가능하다.
- 일정 데이터가 현재 방 기준으로 저장된다.
- 서로 다른 방의 일정 데이터가 섞이지 않는다.
- 동일 방에 접속한 두 브라우저에서 일정 변경이 실시간 반영된다.
- 빈 제목 및 빈 날짜 입력이 차단된다.
- 기존 채팅과 칸반 기능이 정상 동작한다.
- 일정 UI와 데이터 처리 로직이 별도 컴포넌트 또는 hook으로 분리된다.
- lint와 build 검사를 통과한다.
- 테스트 결과와 화면 캡처가 GitHub에 기록된다.
