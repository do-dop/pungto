# AI 기반 일정 CRUD 구현 기록

## 1. 구현 대상

Pungto의 목업 일정 화면을 Supabase 기반 일정 CRUD 기능으로 개선한다.

## 2. 구현 전 기준

이번 구현은 기존 요구사항 명세서, 유스케이스 명세서, 설계 문서, 테스트 계획을 기준으로 수행한다.

## 3. AI 요청 프롬프트

Pungto는 Next.js App Router, TypeScript, React, Supabase를 사용하는 실시간 협업 웹앱이다.

기존 일정 화면은 목업 상태이며, 이번 작업에서는 일정 CRUD 기본 기능을 구현하려고 한다.

요구사항:
- 현재 roomId 기준 일정 목록 조회
- 일정 생성
- 일정 수정
- 일정 삭제
- 제목과 날짜가 비어 있으면 저장하지 않음
- 일정 데이터는 Supabase schedules 테이블에 저장
- 일정 UI와 Supabase 로직은 기존 page.tsx에 직접 누적하지 않고 컴포넌트와 hook으로 분리

설계 기준:
- ScheduleView.tsx: 일정 목록과 전체 UI
- ScheduleFormModal.tsx: 일정 생성/수정 입력 폼
- ScheduleItem.tsx: 개별 일정 표시
- useSchedules.ts: 일정 조회, 생성, 수정, 삭제 Supabase 로직
- types.ts: 일정 관련 타입 정의

이번 PR에서는 Realtime은 구현하지 않고 CRUD까지만 구현한다.

## 4. AI 생성 코드 검토 기준

- 기존 page.tsx에 일정 CRUD 세부 로직을 직접 누적하지 않았는가?
- roomId 기준으로 일정 데이터가 조회 및 저장되는가?
- 제목과 날짜 입력 검증이 존재하는가?
- 일정 생성, 수정, 삭제 실패 시 오류 메시지를 표시하는가?
- Supabase 데이터 로직이 hook에 모여 있는가?
- UI 컴포넌트와 데이터 처리 로직의 책임이 분리되어 있는가?

## 5. 프로세스 적용의 교훈

초기 Pungto 개발에서는 AI에게 포괄적으로 기능 구현을 요청하여 화면 중심의 결과물이 빠르게 생성되었지만, 실제 기능 완성 기준과 코드 구조가 명확하지 않았다.

이번 구현에서는 요구사항 명세서, 유스케이스 명세서, 설계 문서, 테스트 계획을 먼저 작성한 뒤 이를 AI 요청 조건으로 사용하였다. 그 결과 AI를 단순 코드 생성 도구가 아니라, 정의된 프로세스 안에서 구현을 보조하는 도구로 활용할 수 있었다.
