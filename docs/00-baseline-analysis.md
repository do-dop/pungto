# Pungto 초기 구현 상태 분석

## 1. 분석 목적

본 문서는 요구사항 분석, 설계, 테스트 계획, 품질관리 기준 없이 생성형 AI를 활용하여 빠르게 구현된 Pungto의 초기 상태를 분석하기 위해 작성하였다.

초기 Pungto는 화면과 일부 기능을 빠르게 확보하는 데에는 성공했지만, 실제 동작 기능과 목업 기능이 혼재되어 있었고, 기능별 완료 기준과 테스트 기준이 명확하지 않았다. 따라서 본 과제에서는 현재 상태를 베이스라인으로 설정한 뒤, 이후 요구분석부터 품질관리까지의 프로세스를 적용하여 일정 관리 기능을 개선하고자 한다.

## 2. 서비스 개요

Pungto는 사용자가 협업방을 생성하고, 링크 또는 QR 코드를 통해 다른 사용자를 초대하여 함께 사용할 수 있는 실시간 협업 웹앱이다.

주요 기능은 다음과 같다.

- 협업방 생성
- 닉네임 기반 익명 입장
- 실시간 채팅
- 칸반 태스크 관리
- 프로젝트 대시보드
- 참고 링크 공유
- 팀원 역할 관리
- 일정, 자료, 알림, 할 일 화면 제공

## 3. 초기 개발 방식

초기 개발 단계에서는 요구사항 분석서, 기능 우선순위, 설계 문서, 테스트 계획을 먼저 작성하지 않았다.

생성형 AI에게 협업 서비스를 만들어 달라고 요청한 뒤, 생성된 결과물을 확인하면서 UI와 일부 기능을 수정하는 방식으로 개발하였다. 또한 일부 기능은 초기 생성 결과물에 포함된 것이 아니라, 이후 직접 기능 추가를 요청하여 보강하였다. 예를 들어 채팅 메시지는 Supabase와 실시간으로 연동되도록 추가 요청하여 구현한 기능이다.

이 방식은 짧은 시간 안에 여러 화면과 기능을 확보하는 데에는 효과적이었다. 그러나 어떤 기능이 실제로 완성된 기능이고, 어떤 기능이 화면만 존재하는 목업인지 구분하는 기준이 부족하였다.

## 4. 현재 구현 상태

### 4.1 실제 기능으로 구현된 항목

현재 다음 기능은 실제 데이터 저장 또는 실시간 동기화가 적용된 기능이다. 다만 이 항목들은 모두 초기 자동 생성 단계에서 완성된 기능이라는 의미가 아니라, 초기 구현 이후 직접 추가 요청을 통해 보강된 기능도 포함한다.

- 방 생성
- 방 멤버 입장
- 채팅 메시지: Supabase 실시간 연동을 직접 요청하여 보강한 기능
- 칸반 태스크
- 프로젝트 대시보드 정보
- 참고 링크
- 팀원 역할

### 4.2 목업 또는 로컬 상태 중심인 항목

다음 기능은 화면은 존재하지만 실제 협업 기능으로 완성되었다고 보기 어렵다.

- 일정
- 자료 목록
- 알림
- 개인 할 일 목록

특히 일정 기능은 협업 도구에서 중요한 기능처럼 보이지만, 현재는 고정 데이터 또는 화면 중심으로 제공되어 실제 일정 생성, 수정, 삭제, 실시간 공유가 이루어지지 않는다.

## 5. 초기 구현에서 확인된 문제

### 5.1 기능 완료 기준의 부재

초기 개발에서는 각 기능이 어느 수준까지 구현되어야 완료된 것인지 정의하지 않았다. 그 결과 화면은 존재하지만 실제 데이터 저장이나 실시간 협업 기능이 없는 메뉴가 포함되었다.

### 5.2 실제 기능과 목업 기능의 혼재

채팅, 칸반, 대시보드 등은 실제 동작하지만, 일정, 자료, 알림, 할 일은 목업 또는 로컬 상태 중심으로 남아 있다. 이로 인해 서비스 전체의 완성도를 판단하기 어려워졌다.

### 5.3 코드 구조의 복잡성 증가

방 화면의 여러 기능이 하나의 큰 페이지 파일에 집중되어 있어, 기능을 추가하거나 수정할 때 유지보수성이 떨어질 가능성이 있다.

### 5.4 테스트 기준 부족

기능 구현 후 화면에서 동작 여부를 확인하는 수준의 검토는 있었지만, 요구사항 기반의 테스트 케이스, 예외 처리 기준, 회귀 테스트 기준은 명확히 정의되지 않았다.

### 5.5 AI 활용 과정의 통제 부족

초기에는 AI에게 구체적인 요구사항, 설계 기준, 테스트 기준을 제공하기보다 결과 중심으로 구현을 요청하였다. 이로 인해 AI가 빠르게 화면과 코드를 생성했지만, 기능의 일관성이나 품질 기준을 체계적으로 관리하기 어려웠다.

## 6. 개선 대상 선정

본 과제에서는 목업 상태인 일정 기능을 개선 대상으로 선정한다.

선정 이유는 다음과 같다.

- 기존 화면이 존재하여 개선 전후 비교가 가능하다.
- 현재는 실제 협업 기능으로 완성되지 않았으므로 프로세스 적용 효과를 확인하기 좋다.
- 일정 생성, 조회, 수정, 삭제, 실시간 반영 등 요구사항을 명확히 정의할 수 있다.
- 입력 검증, 방별 데이터 분리, 회귀 테스트 등 품질관리 항목을 설정하기 쉽다.
- 일정 관련 코드를 분리하여 설계 원리와 리팩터링의 효과를 함께 확인할 수 있다.
