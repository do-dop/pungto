# 바이브코딩 프로세스 프롬프트 활용 계획

## 목적

이 문서는 앞으로 서비스를 개발할 때 `docs/process/vibecoding-process-prompt.md`를 어떻게 활용할지 정리한 것이다. 이 프롬프트는 실제 서비스 개발 과정에서 AI와 함께 요구사항, 설계, 구현, 검토, 테스트, 품질관리, 형상관리를 일관되게 진행하기 위한 작업 도구이다.

## 활용 방식

- 새 서비스나 새 기능을 시작할 때 먼저 문제 정의와 사용자 범위를 정한다.
- 구현 전에 기능 요구사항, 비기능 요구사항, 제외 범위를 분리한다.
- 설계 단계에서 수정할 파일, 새로 만들 파일, 데이터 모델, API 구조를 먼저 정한다.
- 구현 요청은 한 번에 큰 범위를 맡기지 않고, 검증 가능한 작은 단위로 나눈다.
- AI가 작성한 코드는 바로 반영하지 않고 요구사항, 설계, 보안, 유지보수성 기준으로 검토한다.
- 기능 구현 후에는 lint, build, 주요 동작 테스트 결과를 기록한다.
- GitHub Issue, Branch, Commit, PR에 의사결정과 변경 이유를 남긴다.

## 기대 효과

이 프롬프트를 사용하면 바이브코딩이 빠른 구현에만 치우치지 않고, 개발 전에 무엇을 만들지와 무엇을 만들지 않을지를 먼저 정하게 된다. 또한 설계와 검토 단계를 거치기 때문에 기능이 늘어나도 파일 책임과 데이터 구조가 흐트러질 가능성을 줄일 수 있다. 결과적으로 AI를 단순 코드 생성 도구가 아니라, 개발 절차를 지키도록 돕는 협업 도구로 사용할 수 있다.
